# Граф зависимостей NuGet — вариант 4

CLI-приложение на C++20 получает зависимости NuGet-пакетов через публичный
NuGet V3 API, строит транзитивный граф обходом BFS, выводит описание на D2 и
сохраняет изображение PNG. Для проверки алгоритма есть режим локального
тестового репозитория. Готовые менеджеры пакетов и библиотеки анализа
зависимостей приложение не использует.

## Сборка и запуск

Нужны CMake 3.20+, компилятор C++20 и рендерер D2 или Graphviz (`dot`).
Приложение предпочитает D2, а если он не установлен, строит PNG через
Graphviz. Для обращения к NuGet на Linux также нужен `curl`; на Windows
используется WinHTTP.

```sh
cmake -S . -B .build
cmake --build .build
ctest --test-dir .build --output-on-failure
```

На Linux можно запустить `./run.sh` с теми же параметрами, что и бинарный файл.

```sh
./run.sh --test --package A --repository tests/repository.txt \
  --output outputs/A.png --order
```

Результат: `outputs/A.png` и `outputs/A.d2`. Описание D2 также печатается в
терминал. Если D2 установлен, он строит PNG из файла `.d2`. Иначе Graphviz
строит PNG из того же множества вершин и рёбер.
Список прямых зависимостей исходного пакета также выводится в терминал.

## Параметры

| Параметр | Значение |
| --- | --- |
| `--package ID` | Имя исходного пакета. В тестовом режиме только буквы `A`–`Z`. |
| `--repository URL\|FILE` | URL индекса NuGet V3 либо файл тестового репозитория. |
| `--test` | Использовать файл вместо HTTP-запросов. |
| `--output FILE.png` | Имя изображения; D2 сохраняется рядом с расширением `.d2`. |
| `--order` | Вывести порядок загрузки: зависимости перед зависящим пакетом. |
| `--help` | Показать справку. |

Без `--test` URL должен начинаться с `http://` или `https://`. Пример для
настоящего репозитория:

```sh
./run.sh --package Serilog \
  --repository https://api.nuget.org/v3/index.json \
  --output outputs/Serilog.png --order
```

Программа выбирает для каждого пакета последнюю стабильную версию, а если
стабильных нет — последнюю предварительную. Используются все группы зависимостей
из метаданных выбранной версии. Повторно встреченные пакеты обходятся один раз.

## Тестовый репозиторий и примеры

Формат файла — одна запись `ПАКЕТ: ЗАВИСИМОСТЬ ...` на строку. Имена состоят
из заглавных латинских букв. Пустой список разрешён; `#` начинает комментарий.

```text
A: B C
B: D
C: D
D:
```

Три примера визуализации на `tests/repository.txt`:

```sh
./run.sh --test --package A --repository tests/repository.txt --output outputs/A.png --order
./run.sh --test --package B --repository tests/repository.txt --output outputs/B.png --order
./run.sh --test --package C --repository tests/repository.txt --output outputs/C.png --order
```

Для `A` граф содержит рёбра `A→B`, `A→C`, `B→D`, `C→D`, а порядок равен
`D, B, C, A`. Для `B` и `C` порядок соответственно `D, B` и `D, C`.
Рёбра D2 для `A`:

```d2
"A" -> "B"
"A" -> "C"
"B" -> "D"
"C" -> "D"
```

Для `B`:

```d2
"B" -> "D"
```

Для `C`:

```d2
"C" -> "D"
```

Пакеты `E` и `F` в примере образуют цикл. Граф для `E` выводится, но запрос
`--order` завершается ошибкой: при цикле строгого порядка не существует.

Ошибки параметров также проверяются: отсутствующее имя, несуществующий файл,
имя пакета с недопустимыми символами, неверное расширение результата и
повторение опций вызывают сообщение об ошибке и ненулевой код возврата.
Например, `--package a --test` сообщает, что тестовое имя должно состоять
из `A`–`Z`; `--repository missing.txt --test` сообщает об отсутствующем файле;
`--output graph.svg` требует расширение `.png`; путь без `--test` требует
HTTP URL; `--test=yes` отклоняется как неизвестная опция.

## Сравнение с NuGet

Сравнение проверено 14.11.2026 на временном проекте `net10.0` с пакетом
Serilog 4.4.0. `dotnet package list --include-transitive` показал один пакет:
Serilog, без транзитивных зависимостей. Приложение для того же пакета и
`https://api.nuget.org/v3/index.json` вывело 10 узлов и 12 рёбер. Для
повторения сравнения создайте проект с нужной целевой платформой, добавьте
пакет и выполните:

```sh
dotnet package list --include-transitive
```

В SDK .NET 9 и старше команда называется `dotnet list package
--include-transitive`. Граф этого приложения может содержать больше пакетов,
поскольку он объединяет группы зависимостей **всех** целевых платформ; NuGet
выбирает группу для конкретного проекта. Кроме того, здесь для каждого ID
берётся последняя стабильная версия и не разрешаются диапазоны версий и
конфликты так, как это делает NuGet. Поэтому порядок в `--order` — допустимый
топологический порядок полученного графа, а не фактический порядок скачивания
или установки NuGet. Сравнение требует одинаковой версии пакета и целевой
платформы; текущий CLI не даёт их зафиксировать, поэтому точного совпадения
с результатом `dotnet package list` он не гарантирует.

Тесты запускаются через `ctest` и проверяют PNG, D2, три корневых пакета,
порядок, цикл и ошибки параметров. Сгенерированные файлы и настройки редактора
исключены из Git через `.gitignore`.
